Enterprise AI patterns, one demo each

A Spring Boot 4 + Spring AI 2 sample for the fictional Acme Corp. Every feature has its own use case, seed data and ready-made examples. It runs on a local LLM (LM Studio) and switches to a hosted OpenAI-compatible provider with configuration only.

1 Chat with persistent memory & streaming

Use case: Acme Connect customer support assistant that remembers the customer — even after the app restarts.

How this works behind the scenes →
How it works
  • MessageChatMemoryAdvisor loads the last 20 messages of the conversation and stores each new turn.
  • JdbcChatMemoryRepository persists them in Postgres (spring_ai_chat_memory), keyed by conversation id.
  • ChatClient.stream() returns a Flux<String>, sent to the browser as Server-Sent Events.
  • Demo: send messages 1–2, restart ai-app, then ask message 2 again with the same conversation id.

2 Guardrails

Use case: Acme Bank public chat — protect customers' data and keep the assistant on its job.

How this works behind the scenes →
How it works
  • Guardrails are ChatClient advisors that run before the memory advisor, so nothing unsafe is sent to the model or stored.
  • PiiRedactionAdvisor masks emails, card numbers (Luhn-checked), IBANs, phone and SSN-style numbers.
  • PromptInjectionAdvisor blocks jailbreak patterns (HTTP 400, RFC 9457 problem detail); optional LLM classifier.
  • Spring AI's SafeGuardAdvisor enforces a denylist; TopicGuardAdvisor refuses off-topic requests without calling the model.
  • OutputGuardAdvisor withholds answers that leak the system prompt and masks PII in the answer.

3 RAG with citations

Use case: HR & IT policy Q&A for Acme employees, answered only from the handbook — with sources.

How this works behind the scenes →
How it works
  • Ingestion (ETL): TikaDocumentReader (PDF, DOCX, MD…) → TokenTextSplitter → metadata (source, category, sha256) → PgVectorStore.
  • Answering: RetrievalAugmentationAdvisor with VectorStoreDocumentRetriever (top-k, similarity threshold, metadata filter).
  • ContextualQueryAugmenter numbers the sources for citations and answers "not found" when nothing relevant is retrieved.

4 Tool calling with human-in-the-loop

Use case: IT helpdesk agent that looks up employees and laptops, opens tickets — and asks a human before risky actions.

How this works behind the scenes →
How it works
  • Business methods are exposed with @Tool; the model decides which to call and with which arguments.
  • Spring AI 2 runs the tool loop in ToolCallingAdvisor. A custom ToolCallingManager lets safe tools run and pauses on methods marked @RequiresApproval.
  • The paused conversation is parked; Approve executes the call and resumes the agent, Reject tells the agent it was not done.
  • Seed data (Flyway): 8 employees, 10 assets, 6 tickets. Every action is written to an audit log.

6 Structured extraction

Use cases: accounts-payable invoice processing and meeting notes → action items.

How this works behind the scenes →
How it works
  • ChatClient…entity(Invoice.class) with useProviderStructuredOutput(): the JSON schema of the Java record is sent as response_format — the model can only produce matching JSON.
  • Jakarta Bean Validation enforces business rules the schema can't express (custom @TotalsMatch: line items = subtotal, subtotal + tax = total).
  • Violations are fed back for another attempt; if the document itself is wrong, the result is flagged needsReview for a human.

8 Observability

Use case: AI operations — what does each feature cost in tokens, how slow is it, which tools run, what do guardrails block?

How this works behind the scenes →
How it works
  • Spring AI emits Micrometer observations for every ChatClient call, advisor, model call (gen_ai.*), tool call and vector search.
  • Spring Boot 4's OpenTelemetry starter exports traces and metrics via OTLP to the grafana/otel-lgtm container (Tempo + Prometheus + Grafana).
  • FeatureMetricsAdvisor adds the business dimension: tokens and latency per showcase feature.
  • Prompt/completion content is not recorded by default (PII); enable via spring.ai.chat.client.observations.log-prompt.

9 LLM evaluation (quality gate)

Use case: RAG quality gate in CI — catch answer-quality regressions before they ship.

How this works behind the scenes →
How it works
  • A golden set of questions with known answers runs through the real RAG pipeline.
  • Each answer is graded on expected facts (deterministic), relevancy (RelevancyEvaluator) and groundedness (FactCheckingEvaluator) — LLM-as-judge.
  • The same service backs the JUnit suite: ./mvnw verify -Pllm-eval fails the build below the pass-rate threshold.
  • Regression demo: rerun with top-k 1 and threshold 0.95 — retrieval starves and the gate fails.
Takes 1–2 minutes on a local 4B model.

10 Text-to-SQL

Use case: Ask the helpdesk data — IT managers ask about tickets, laptops and employees in plain English.

How this works behind the scenes →
How it works
  • The model sees the schema of three allow-listed tables, built from Postgres COMMENTs that carry the business meaning ("out of warranty means warranty_until < today").
  • It returns {reasoning, sql} as structured output. SqlGuard parses the SQL with JSqlParser: one SELECT, allow-listed tables only, no dangerous functions, LIMIT clamped to 200.
  • The query runs in a read-only transaction with a 3 s statement timeout, so the database refuses writes even if the guard were bypassed.
  • A database error goes back to the model for one repair attempt. A second, short LLM call explains the returned rows.

11 Semantic caching

Use case: don't pay twice for the same question — employees ask the same policy questions in different words; repeats are answered from pgvector.

How this works behind the scenes →
How it works
  • SemanticCacheAdvisor runs first in the RAG demo's ChatClient. It embeds the question and finds the closest cached question in a second pgvector table, semantic_cache.
  • Similarity at or above the threshold (0.95) returns the cached answer and citations without retrieval or a model call. Below it, the normal RAG pipeline runs and its answer is stored.
  • Entries are kept apart by feature, retrieval settings and model, expire after 24 h, and are dropped whenever a document is ingested or deleted.
  • Only stateless answers are cached: never chat with memory, helpdesk actions or anything personal.

The test clears the cache, asks one policy question for real (a miss), asks it again (a hit), then probes five rewordings against it without calling the model.

12 Multi-agent with A2A

Use case: the helpdesk agent asks the procurement agent — another team's AI agent, in its own service, reached over the Agent2Agent protocol.

How this works behind the scenes →
How it works
  • Discovery: the procurement agent (procurement-agent, port 8082) publishes an agent card at /.well-known/agent-card.json: name, endpoint, transport and skills with examples.
  • Messaging: callers send a JSON-RPC message/send. The agent answers with a task: a state (submitted → working → completed, or input-required / failed), a history of status messages, and artifacts (a text summary and the purchase request as data).
  • Opaque by design: callers never see the other agent's prompt, tools or model. That is the difference from MCP, where the caller's own model drives the remote tools.
  • The helpdesk tool requestHardwarePurchase uses the A2A Java SDK client and waits for human approval, because it spends budget.
